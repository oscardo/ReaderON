Rol: Actúa como un Desarrollador Senior de Android especializado en Java, integraciones de IA y procesamiento de lenguaje natural.
Tarea: Diseñar la arquitectura y proporcionar el código base para una aplicación en Android Studio (Java) llamada "ReaderON".
Contexto de la App: ReaderON es una herramienta educativa bilingüe (Inglés/Español) que permite al usuario tomar una foto de un texto, extraerlo mediante OCR, leerlo en voz alta mientras se graba, y finalmente evaluar la precisión de su lectura comparando el audio con el texto original.

Módulos y Requerimientos Técnicos:

1. Módulo de OCR y Gestión de Archivos:
Integrar la cámara para tomar una foto y permitir el recorte de la imagen.
Usar Google ML Kit (Vision OCR) (que es gratuito y offline) para extraer el texto de la imagen recortada.
Guardar este texto en almacenamiento local bajo la nomenclatura transcription_ddmmyyyy_hhmm.Play. (Nota: Trata la extensión .Play internamente como un archivo JSON o HTML para soportar texto enriquecido más adelante).

2. Módulo de Grabadora de Audio:
Interfaz con botones de iconos. Al mantener presionado un botón (usando TooltipCompat), debe mostrar su nombre según el idioma del sistema (Inglés/Español).
Controles requeridos: Ir al inicio, Atrás, Play, Pausa, Grabar, Terminar grabación, Adelante, Ir al final.
Control de velocidad de reproducción: 0.5x, 1.0x, 1.5x, 1.75x, 2.0x, 2.5x, 3.0x.
Implementar autoguardado periódico durante la grabación para evitar pérdida de datos.
Guardar el archivo final como audio_ddmmyyyy_hhmm.mp3.

3. Módulo de Análisis Sintáctico y de Pronunciación (El Core):
Al terminar la grabación, la app debe comparar el audio grabado con el texto original del OCR.
Para esto, sugiere una API gratuita o un modelo local (como Vosk Speech Recognition para pasar el audio a texto offline) y un algoritmo de comparación de cadenas (como la distancia de Levenshtein) para evaluar la precisión de cada frase/palabra.
Generar el texto enriquecido en el archivo .Play aplicando las siguientes reglas de estilo según el porcentaje de coincidencia de lo leído vs lo escrito:
0% al 30%: Fuente roja, resaltado rojo (Considerar accesibilidad visual).
31% al 54%: Fuente roja, resaltado amarillo.
55% al 74%: Fuente amarilla.
75% al 100%: Fuente verde.
Mostrar al final del texto el porcentaje de precisión total (promedio general).

4. Módulo de Resumen con IA:
Integrar la API gratuita de Gemini (Google AI Studio).
Enviar el texto del OCR a la API para generar un análisis que extraiga: datos de interés, lo más importante, entidades (servicios, servidores, aplicaciones).
Guardar este análisis en un archivo llamado resumen_ddmmyyyy_hhmm.Play.
Entregables que necesito de ti (IA):
Estructura de dependencias de build.gradle (librerías OCR, Audio, Vosk, Gemini).
Código para el flujo de la cámara y OCR.
Código de la grabadora y el manejo de persistencia de archivos.
Lógica en Java para la comparación de texto y asignación de colores (Span/HTML).
Haz que el código priorice la facilidad de uso e incluya comentarios explicativos.

El formato .Play no existe de forma nativa: Android no sabe cómo leer un archivo .play con colores, La solución técnica (que incluí en el prompt) es que tu app internamente guarde y procese este archivo como un HTML (usando HtmlCompat.fromHtml en Android) o como un JSON que guarde la palabra y su porcentaje, Al usuario se le mostrará como un archivo .Play, pero tu código lo tratará como HTML.
Contraste de colores (UX/UI): Mencionas que de 0% a 30% la fuente debe ser roja con resaltado rojo. Esto hará que el texto sea invisible. Te sugiero usar fuente blanca con resaltado rojo para ese rango, o mantener la fuente negra y solo cambiar el color de fondo (resaltado).
Velocidades negativas de audio: En tu lista de controles incluiste -2x, -1.5x, -1x. En procesamiento de audio, una velocidad negativa implica reproducir el audio en reversa, lo cual requiere algoritmos complejos (Audio DSP) y rara vez es útil para evaluar pronunciación. Es mejor mantener los controles de 0.5x a 3.0x o implementar botones de "Retroceder 10 segundos".
"Cuando pase un segundo encima de un botón" (Hover): En dispositivos móviles táctiles no existe el "hover" (pasar el mouse por encima). La alternativa nativa y estándar en Android es el Long Press (mantener presionado). En el prompt lo traduje al uso de TooltipCompat, que es la práctica oficial de Android para mostrar labels al mantener presionado un ícono.
El desafío del "Analizador Gratuito": * Para comparar la precisión de la pronunciación sin pagar, la mejor ruta es usar Vosk (una librería de IA offline que corre en el propio celular). Escuchará el mp3, lo pasará a texto, y luego tú en Java comparas el texto de Vosk con el texto del OCR.
Para la parte del resumen (datos de interés, entidades, etc.), la API de Gemini ofrece una capa gratuita generosa para desarrolladores.
Sincronización: Hacer el traslape exacto para que el audio suene al mismo tiempo que se ilumina la palabra (estilo karaoke) requiere guardar los timestamps (marcas de tiempo) de cada palabra. Vosk permite extraer timestamps por palabra, lo cual será clave para tu analizador sintáctico.

			pantalla de esta (Cleft sentences)
			A cleft sentence is a complex sentence structure that splits a single idea into two clauses to emphasize a specific part of the sentence, such as the subject, object, or adverbial phrase. It converts a simple sentence into a main clause (often starting with "It is/was" or "What") and a relative clause to highlight new information. 
			Key Characteristics and Examples:
			"It-Clefts": Starts with It + be + emphasized part + that/who.
			Normal: John stole the cookie.
			Cleft: It was John who stole the cookie. (Emphasizes it was John, not someone else).
			"What-Clefts" (Wh-Clefts): Starts with What + subject + verb + be + emphasized part.
			Normal: I need a coffee.
			Cleft: What I need is a coffee. (Emphasizes the need is coffee).
			Purpose: To focus on new information or contrast information while connecting it to what is already understood by the listener.
			Usage: Commonly used to emphasize time, place, or specific people.
			Example: It was in the park that I lost my keys. 
			Common Cleft Structures:
				It + be + noun phrase + that/who: It was the manager that I spoke to.
				What + clause + be + phrase: What I don't understand is why she left.
				It + be + adverbial phrase + that: It was yesterday that they arrived.
				
			descripcion en español:
			Una oración hendida es una estructura sintáctica compleja que divide una sola idea en dos cláusulas para enfatizar una parte específica de la oración, como el sujeto, el objeto o un complemento. Convierte una oración simple en una cláusula principal (que suele empezar con "It is/was" o "What") y una cláusula relativa para resaltar información nueva.

			Características clave y ejemplos:
			Oraciones cleft con "It": Comienzan con "It" + "be" + la parte enfatizada + "that/who".
			Oración normal: John robó la galleta.
			Oración cleft: Fue John quien robó la galleta. (Enfatiza que fue John, no otra persona).
			Oraciones cleft con "What" (o "Wh-Clefts"): Comienzan con "What" + sujeto + verbo + "be" + la parte enfatizada.

			Oración normal: Necesito un café.
			Oración cleft: Lo que necesito es un café. (Enfatiza que la necesidad es el café).
			Propósito: Centrarse en información nueva o contrastar información, conectándola con lo que el oyente ya comprende. Uso: Se utiliza comúnmente para enfatizar el tiempo, el lugar o personas específicas.
			Ejemplo: Fue en el parque donde perdí mis llaves.
			Estructuras comunes de oraciones hendidas:
			It + be + sintagma nominal + that/who: Fue el gerente con quien hablé.
			What + cláusula + be + sintagma: Lo que no entiendo es por qué se fue.
			It + be + sintagma adverbial + that: Fue ayer cuando llegaron.

import android.content.Context
import com.google.mediapipe.tasks.genai.llminference.LlmInference
import kotlinx.coroutines.Dispatchers
import kotlinx.coroutines.withContext

class GemmaInferenceManager(private val context: Context) {

    private var llmInference: LlmInference? = null

    suspend fun initLlm(modelPath: String) {
        withContext(Dispatchers.IO) {
            try {
                val options = LlmInference.LlmInferenceOptions.builder()
                    .setModelPath(modelPath)
                    .setMaxTokens(1024) // Ajusta según la longitud de resúmenes que necesites
                    .setTemperature(0.7f)
                    .build()
                
                llmInference = LlmInference.createFromOptions(context, options)
            } catch (e: Exception) {
                e.printStackTrace()
            }
        }
    }

    // Método para interactuar con la IA
    suspend fun generateResponse(prompt: String): String? {
        return withContext(Dispatchers.IO) {
            llmInference?.generateResponse(prompt)
        }
    }
    
    fun close() {
        llmInference?.close()
    }
}
